FISHING CHAT GAME 1.0.0 — GITHUB E RELEASE

1. BAIXAR E EXTRAIR
Baixe Fishing-Chat-Game-v1.0.0-GitHub.zip em Downloads.
Clique com o botão direito > Extrair Tudo.
Abra a pasta extraída. Você verá package.json, package-lock.json, src,
tests e INICIAR.bat. Esse é o nível correto para enviar ao GitHub.

2. SUBSTITUIR OS ARQUIVOS DO REPOSITÓRIO
Abra https://github.com/jumperjjj/fishing-chat-game
Confira que a branch selecionada é main.
Clique em Add file > Upload files.
Na pasta extraída, selecione as pastas src e tests e os arquivos soltos
(package.json, package-lock.json, README.md, INICIAR.bat, os .txt e .md).
Arraste essa seleção para a área de upload. Selecione .gitignore também.
Deixe a pasta .github para o próximo passo.
NÃO arraste a pasta externa Fishing-Chat-Game-v1.0.0-GitHub nem o ZIP.
Os caminhos na tela devem ser src/main.js, package.json etc., sem outra
pasta na frente. Os arquivos com o mesmo caminho substituem os antigos.
Confira que package-lock.json e todos os arquivos de src e tests estão lá.
Escreva a mensagem: Preparar Fishing Chat Game 1.0.0
Escolha Commit directly to the main branch e clique em Commit changes.
Não precisa apagar o repositório. ARQUIVOS-GITHUB.txt lista as substituições.

3. ATUALIZAR O ACTION QUE JÁ EXISTE
Não crie outro workflow com outro nome.
Abra este arquivo no GitHub:
https://github.com/jumperjjj/fishing-chat-game/blob/main/.github/workflows/build-windows.yml
Clique no lápis para editar.
Na pasta extraída, abra build-windows-PARA-COPIAR.txt no Bloco de Notas.
Ctrl+A, Ctrl+C. Volte ao editor do GitHub, selecione todo o conteúdo
antigo e cole o novo. O nome continua build-windows.yml.
Clique em Commit changes e salve na branch main.
O TXT é uma cópia do YAML para facilitar; o GitHub executa o arquivo
.github/workflows/build-windows.yml, não o TXT.

4. PUBLICAR A VERSÃO CORRETA
Volte à página do repositório > Releases > Draft a new release.
Em Choose a tag, digite v1.0.0 e escolha criar essa nova tag.
Em Target, escolha main, já com os arquivos dos passos 2 e 3.
Título: Fishing Chat Game 1.0.0
Copie a descrição de RELEASE-NOTES-v1.0.0.md se quiser.
Clique em Publish release. Não marque como pré-release.
Use exatamente v1.0.0; não use v1.10.0.
Não precisa anexar o ZIP do projeto nem um EXE manualmente.

5. AGUARDAR O EXE
Abra a aba Actions > Build Windows > execução referente a v1.0.0.
O GitHub instala as dependências, verifica o código, roda os testes e
gera o instalador. Aguarde o resultado verde.
Volte ao release v1.0.0 e atualize a página.
Em Assets aparecerá Fishing-Chat-Game-Setup-1.0.0.exe.
Baixe ESSE arquivo para instalar. Source code (zip) não é o instalador.
Se o Action ficar vermelho, abra a etapa vermelha e envie o erro.
Após corrigir, na execução use Re-run failed jobs ou Re-run all jobs.

OPCIONAL: COMPILAR ANTES DE PUBLICAR
Depois do passo 3, Actions > Build Windows > Run workflow > main > Run workflow.
Quando terminar, abra a execução e baixe o artifact Fishing-Chat-Game-Windows.
Extraia esse ZIP para encontrar o EXE. Essa execução manual só gera o
artifact; publicar o release no passo 4 dispara outra execução que anexa
o EXE automaticamente ao release.

6. PRIMEIRA ABERTURA E RESET SOLICITADO
Feche as versões anteriores antes de instalar/abrir a 1.0.0.
A PRIMEIRA abertura da 1.0.0 salva um backup e zera o progresso de todos
os jogadores, em todos os canais: ouro, ranking, coleção, conquistas
obtidas e histórico. Os eventos ativos de teste são encerrados.
O catálogo de peixes/itens, suas imagens, as definições de conquistas e
as configurações do bot, comandos e overlays são preservados.
O reset acontece UMA VEZ. Fechar e abrir novamente mantém o progresso novo.
O backup fica na pasta de dados do aplicativo, em backups/before-1.0.0-...,
com fishing-game.db e item-images. Se o backup falhar, não limpa o progresso.
O ZIP não contém seu banco pessoal nem tokens de autorização.
Seu banco atual ainda não foi alterado ao preparar este pacote.

TESTE LOCAL SEM EXE
Você ainda pode abrir INICIAR.bat na pasta extraída, com Node.js 24 instalado.
A PRIMEIRA abertura por INICIAR.bat também executa esse reset da 1.0.0.
Mantenha a janela de terminal aberta durante o teste.
Depois da atualização, recarregue as fontes de navegador do OBS.
Teste Twitch e OBS na live: os testes automatizados não substituem isso.
